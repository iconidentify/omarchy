# Session lock recovery

Omarchy records lock intent in `~/.local/state/omarchy/session-guard/locked` before asking the compositor to lock. Password or fingerprint authentication clears it before the protocol unlock. A failed state write never counts as a secure lock; a failed clear leaves the existing protocol lock in place.

The Omarchy UWSM session starts `omarchy-guarded-hyprland.desktop`. Its supervisor holds a single-compositor lease and checks intent before executing Hyprland. A crash while locked returns to the greeter. Another compositor is never started and then locked after drawing the desktop. The marker survives reboot, so a subsequent autologin cannot clear it. An authenticated SDDM login clears it through the `sddm` PAM open-session hook. The `sddm-autologin` stack has no such hook, and SDDM automatic relogin is disabled.

Deploy the matching runtime and settings packages together, with a new shared package version and identical source pins so the runtime's exact-version settings dependency forces a paired upgrade. Settings must install both desktop entries and `/etc/sddm.conf.d/90-session-lock-recovery.conf`; runtime must install the helper and its Python implementation and depend on Python. Run `sudo python3 -I /usr/share/omarchy/shell/session-guard-install.py` only after those assets exist. Setup checks their binding and the effective SDDM relogin policy before changing PAM and can be repeated. New installs run the same setup through `install/login/all.sh`; updates run it through the paired post-transaction hook. Do not start a new session during a split runtime/settings upgrade.

The authenticated hook belongs only in `/etc/pam.d/sddm`, after the existing session stack. Never add it to `sddm-autologin`, a greeter stack or an unconditional startup command. A local `/etc/sddm.conf` can override package drop-ins; deployment must check the effective `Relogin=false` policy before admitting this configuration. Keep custom compositor entry points out of the guarded profile until they execute the same supervisor.

For rollback, first authenticate and end the graphical session. `sudo python3 -I /usr/share/omarchy/shell/session-guard-install.py --rollback` removes only the owned PAM line. Then restore both runtime/settings packages and their desktop entries together. Do not delete a lock-intent marker to recover an unauthenticated desktop. If state permissions are invalid, authenticate on a TTY before repairing them.

Command tests cover queued replacements, compositor termination, first-exec denial, persistent intent with a fresh runtime directory, marker failures, authenticated versus autologin PAM dispatch, repeated setup and rollback. They do not establish that any particular compositor crash is fixed or replace physical suspend, greeter and password/fingerprint acceptance on the deployed versions.
